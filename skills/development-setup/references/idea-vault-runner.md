# 利用者自身のGitHubへのRunner導入

本手順は、利用者が自動開発の実行環境の導入を依頼した場合に使用する。
エージェントは、既存の依頼範囲に含まれる工程を継続する。
通常の企画保存やスキル作成だけでは、エージェントは認証や配置を開始しない。

## 配布物と配置先

| 対象 | 所有者・配置先 |
|---|---|
| プラグインの配布元 | 配布者が所有する。利用者は配布元のリポジトリを作り直さない。 |
| 制御プログラムの同梱版 | このスキルの `assets/runner-template/` に含まれる。 |
| 導入プログラム | このスキルの `scripts/install_runner.py` を使用する。 |
| 企画管理用リポジトリ | 利用者自身が所有する。未指定時の名前は `idea-vault`。 |
| 非公開の実行用リポジトリ | 利用者自身が所有する。未指定時の名前は `idea-vault-runner`。 |

エージェントは、配布者のアカウント名や非公開リポジトリを導入先へ流用しない。
エージェントは、同梱した[運用手順](../assets/runner-template/docs/OPERATIONS.md)を参照する。
利用者は、配布者の非公開リポジトリへアクセスする必要がない。

## 1. 利用機能・環境・本人を確認する

エージェントは、利用者のシェル・Python・Git・GitHub CLIを確認する。
CLIを実行できない場合、エージェントは利用者の端末向け手順を案内する。
スキルの追加だけでは、端末の操作権限は増えない。

エージェントは、利用するGitHubアカウントと配置先を確認する。
既存の会話や設定で確定した値は、エージェントが再利用する。
未確認の項目だけを、エージェントは利用者へ質問する。
本人認証が不足する場合、エージェントは[GitHub CLIの手順](github-cli.md)で認証を進める。
利用者は、公式ブラウザ画面で本人認証と必要な権限承認を行う。

## 2. 同梱版と配置計画を確認する

エージェントは、プラグインのキャッシュ外に利用者専用の作業フォルダを選ぶ。
エージェントは、次のプレビューを実行する。

```bash
python3 <skill-dir>/scripts/install_runner.py --workspace <利用者専用の作業フォルダ>
```

`<skill-dir>` は、このスキルの実際のディレクトリへ置き換える。
導入スクリプトは、同梱版のファイル一覧とチェックサムを確認する。
導入スクリプトは、ログイン中の本人と配置先を確認する。
プレビューは、リポジトリの作成・push・Secrets登録を行わない。

| 引数 | 用途 |
|---|---|
| `--owner LOGIN` | 期待する利用者の個人ログイン名を指定する。 |
| `--ideas-repository OWNER/REPO` | 利用者の企画管理用リポジトリを指定する。 |
| `--runner-repository OWNER/REPO` | 利用者の非公開実行用リポジトリを指定する。 |
| `--create-ideas` | 依頼済みの企画管理用リポジトリが未作成の場合に作成する。 |
| `--gh PATH` | 利用するGitHub CLIの実行ファイルを指定する。 |
| `--git PATH` | 利用するGitの実行ファイルを指定する。 |
| `--apply` | 確認した計画に従って配置する。 |

未指定のリポジトリ名には、ログイン中の本人のアカウントを使用する。
エージェントは、指定済みの保存先を既定名へ変更しない。

## 3. 利用者用設定を生成してpushする

エージェントは、確認した引数へ `--apply` を追加する。
既存の依頼が配置を許可している場合、エージェントは同じ許可を繰り返し求めない。

導入スクリプトは、次の処理を実行する。

1. 導入スクリプトは、同梱版を利用者専用の作業フォルダへ展開する。
2. 導入スクリプトは、利用者の所有者・企画保存先・実行先を設定する。
3. 導入スクリプトは、Actionsが読む `config/runner.yaml` を生成する。
4. 導入スクリプトは、利用者本人の非公開実行用リポジトリを作成する。
5. 導入スクリプトは、設定済みコードとActions設定をcommitしてpushする。

新しい作業コピーは、配布者のGit履歴やoriginを引き継がない。
新規配置のpushは、GitHub CLIの認証を使うHTTPS経路を利用する。
導入スクリプトは、利用者のSSH鍵やグローバルGit設定を変更しない。
導入スクリプトは、企画や時間設定の既存データを保持する。
導入スクリプトは、既存の公開リポジトリを非公開へ変更しない。
初回配置の `RUNNER_ENABLED` は、`false` とする。

再実行時、エージェントは導入記録・配置先・利用者の変更を確認する。
エージェントは、無関係なリポジトリや変更済みファイルを強制上書きしない。
費用停止の記録は、再配置や請求月の更新でも維持する。

## 4. 依頼されたCI認証を登録する

| 認証 | 用途・必要な権限 |
|---|---|
| `RUNNER_GITHUB_TOKEN` | 開発先の作成、企画の読取、実行用Contents・Secrets・Variables・Workflowの更新、使用量の読取。 |
| `DEVELOPMENT_GITHUB_TOKEN` | 開発先のContents・Issues・Pull requestsの更新。 |
| `CODEX_AUTH_JSON` | CI専用のChatGPT認証。 |
| `QUOTA_NOTIFICATION_TOKEN` | Actionsが `github.token` から渡す通知用bot認証。利用者によるSecret作成は不要。 |

エージェントは、利用者が指定した非公開実行用リポジトリへSecretsを登録する。
利用者は、管理用と開発用に別々のGitHubトークンを用意する。
利用者は、公式CLIの対話入力などの安全な経路でトークンを登録する。
エージェントは、トークンの会話への貼り付けを求めない。

```bash
gh secret set RUNNER_GITHUB_TOKEN --repo OWNER/REPO
gh secret set DEVELOPMENT_GITHUB_TOKEN --repo OWNER/REPO
```

`OWNER/REPO` は、利用者が指定した非公開実行用リポジトリへ置き換える。
エージェントは、[Codexの手順](codex.md)でCI専用の認証を用意する。
エージェントは、通常のIDE認証やPC用のGitHub認証をCIへ無断で複製しない。
エージェントは、変更依頼のない既存Secretsを上書きしない。
ワークフローは、通知用botへ `issues: write` を付与する。
制御プログラムは、管理用・通知用の認証を開発用子プロセスへ渡さない。

## 5. 配置・認証・運用条件を別々に検証する

| 判定 | 必要な根拠 |
|---|---|
| 配置完了 | 本人の非公開リポジトリに、コード・利用者設定・Actions設定・導入記録が存在する。 |
| CI認証の成功 | 対象CIでの認証結果を確認する。Secrets名の存在だけでは完了にしない。 |
| 更新認証の保存 | 実際に更新されたCodex認証を保存した結果を確認する。 |
| 運用開始 | 費用条件、利用者の時間指定、企画の開発許可、運用開始の依頼を確認する。 |

導入スクリプトの `deployed` と `verified_existing` は、配置に関する結果を表す。
`deployment_complete` は、CI認証や運用条件の検証結果を代替しない。
エージェントは、`unverified_steps` に残る工程と担当者を利用者へ示す。
エージェントは、`full_setup_complete: false` をセットアップ完了と読み替えない。

利用者は、GitHub側の利用停止設定・契約枠・請求期間・実際の残枠を確認する。
エージェントは、費用データを推測で埋めない。
現行Runnerは、公式使用量と利用者の確認データを照合する。
現行Runnerは、既定で60分より古い確認データを拒否する。
したがって、配置完了だけでは無人継続運用の完成を意味しない。
残枠データの取得・更新方式は、利用者の運用条件として確認する必要がある。

Actionsは、Node・Codex・Symphonyの導入前に `quota-check` を実行する。
`doctor` は、モデルを呼び出さずに設定を検証する。
`auth-check` は、費用条件を満たした場合だけCodexのCI認証を検証する。
CI検証が依頼に含まれる場合、エージェントは許可された範囲で実証する。
実証専用に起動設定を変更した場合、エージェントは実証後に元へ戻す。

残枠500分以下を検出すると、Runnerは自動開発を永続停止する。
通知用botは、利用者本人宛ての警告Issueを作成する。
メール配信の有無は、利用者本人のGitHub通知設定に従う。
通知の失敗や残枠の回復は、停止状態を解除しない。
費用停止後の利用再開方法は、未定である。
既存の企画用 `resume` は、費用停止を解除しない。

エージェントは、各判定の結果と残作業の担当者を報告する。
エージェントは、配置や認証の成功だけを理由に自動実行や開発許可を有効にしない。
