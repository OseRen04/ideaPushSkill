# Codexのログインワークフロー

## 認証対象の判定

エージェントは、利用者の端末用ログインとCI用ログインを区別する。
エージェントは、利用者の指定環境と認証方式を特定する。
Idea Vault Runnerでは、利用者のChatGPT契約による認証を使用する。
エージェントは、認証不調を理由にAPIキー認証へ切り替えない。

エージェントは、`codex --version` と `codex login --help` を確認する。
エージェントは、指定した環境で `codex login status` を実行する。
エージェントは、CLI出力から秘密を含まないログイン状態だけを報告する。

```bash
codex login status
```

既存の認証が目的に適合する場合、エージェントはローカルの再ログインを省略する。
既存認証がAPIキー方式の場合、エージェントは既存認証を勝手に置き換えない。
利用者の依頼範囲で、エージェントはChatGPT認証用の環境を分ける。
エージェントは、`auth.json` の本文を状態確認のために表示しない。

## 利用者の端末用ログイン

エージェントは、既存のログインが未設定・無効な場合に公式ログインを開始する。

```bash
codex login
```

利用者は、公式のブラウザ画面でChatGPTアカウントへログインする。
エージェントは、公式CLIが返したURLと手順を案内する。
エージェントは、正常終了後に `codex login status` を再確認する。

ブラウザの折り返しが使えない環境では、デバイス認証を利用できる場合がある。
エージェントは、CLIと利用者のアカウント側の対応を確認する。

```bash
codex login --device-auth
```

利用者は、公式CLIが示したURLへアクセスして一時コードを入力する。
認証コードの期限切れでは、エージェントは新しいセッションから再開する。
デバイス認証が利用不可の場合、エージェントは公式ブラウザ認証へ戻る。

## CI専用の認証

エージェントは、利用者がCI用の認証設定を依頼した場合だけ本工程を進める。
エージェントは、登録先の所有者と非公開設定を確認する。
エージェントは、公開リポジトリ向けにChatGPT認証情報を配置しない。

エージェントは、タスク専用のディレクトリを権限700で作成する。
エージェントは、専用ディレクトリをGitや共有Artifactの管理対象から外す。
エージェントは、`CODEX_HOME` をログイン用の子プロセスだけへ渡す。
エージェントは、利用者の通常の `CODEX_HOME` を上書きしない。

次の形式は、専用ディレクトリで認証する操作例である。
`TASK_CODEX_HOME` は、エージェントが作成した専用ディレクトリを指す。

```bash
CODEX_HOME="$TASK_CODEX_HOME" codex -c 'cli_auth_credentials_store="file"' login
CODEX_HOME="$TASK_CODEX_HOME" codex login status
```

エージェントは、必要な場合だけ専用環境でも `--device-auth` を使う。
利用者は、専用環境のためにブラウザ認証を完了する。
エージェントは、管理認証の方式と更新用情報の存在だけを検証する。
エージェントは、認証情報の値を表示しない。

Secretsへの登録では、エージェントは対象を明示して標準入力を使う。

```bash
gh secret set CODEX_AUTH_JSON --repo OWNER/REPO < "$TASK_CODEX_HOME/auth.json"
```

エージェントは、登録成功と保存先を確認する。
エージェントは、自分が作成した一時的な認証情報だけを後片付けする。
エージェントは、登録に失敗した状態を完了として報告しない。
利用者が後で再開する場合、エージェントは専用認証の保持・再生成を明示する。
エージェントは、利用者の通常の認証情報を削除しない。

## 検証と運用への引き継ぎ

`codex login status` は、ローカルのログイン状態の根拠とする。
エージェントは、ローカルの状態だけでサーバー側の認証成功を断定しない。
エージェントは、CI用Secretsの名前だけで認証内容の正しさを断定しない。
CIでのモデル実行は、利用者が依頼した動作検証の工程で扱う。
エージェントは、検証前にプロジェクトの費用条件を確認する。

CIは、最新の認証情報を復元してCodexを実行する。
Codexは、認証情報を必要に応じて更新する。
CIは、更新された認証情報を安全な保存先へ書き戻す。
CIは、同じ認証情報を使う実行を直列化する。
利用者は、実行用の認証情報を他の端末と共用しない。
認証が失効した場合、エージェントは専用ログインから復旧する。

エージェントは、認証成功と更新・書き戻しの実証を区別する。
認証が更新されなかった場合、エージェントは更新経路を実証済みと報告しない。

公式資料は、[Codexの認証](https://learn.chatgpt.com/docs/auth)と[CI認証](https://learn.chatgpt.com/docs/auth/ci-cd-auth)を参照する。
