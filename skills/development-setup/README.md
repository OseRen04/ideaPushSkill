# 初期セットアップの流れ（5W1H）

| 項目 | 内容 |
| --- | --- |
| When（いつ） | あなたは、初回導入時や認証失効時にセットアップを依頼します。エージェントは、あなたがブラウザを操作できる時点で認証を開始します。 |
| Where（どこで） | エージェントは、あなたの端末で公式CLIを操作します。あなたは、GitHubとOpenAIの公式画面で本人認証を行います。CI設定の対象は、あなたの非公開リポジトリ `OseRen04/idea-vault-runner` です。CI用の認証情報の登録先は、実行用リポジトリのSecretsです。 |
| Who（誰が） | あなたは、本人認証と権限承認を担当します。CI設定を依頼する場合、あなたはCI用トークンの準備と費用条件の確認も担当します。エージェントは、診断・案内・設定・検証を担当します。 |
| What（何を） | エージェントは、あなたのGitHub CLIの認証・権限とCodexのChatGPT認証を設定します。CI設定が依頼に含まれる場合、エージェントはCI専用認証とSecretsを登録します。 |
| Why（なぜ） | 初期セットアップの目的は、あなたのGitHub操作とCodex利用に必要な認証を整えることです。CI設定の目的は、あなたのGitHub Actionsで専用認証を利用することです。 |
| How（どのように） | ① あなたは、[初期セットアップスキル](SKILL.md)へ「初期セットアップを進めて」と依頼します。<br>② エージェントは、診断→不足の整理→認証→登録→検証の順で進めます。利用可能な既存認証がある場合、エージェントは再認証を省略します。<br>③ コードが期限切れの場合、エージェントは新しいコードで未完了の認証を再開します。<br>④ CI検証が依頼に含まれる場合、エージェントは権限と費用条件を確認します。権限と費用条件が揃った場合だけ、エージェントはCIの接続を別途検証します。<br>⑤ エージェントは、ローカル認証とCIの検証結果を分けて報告します。エージェントは、残作業と担当者も報告します。 |
